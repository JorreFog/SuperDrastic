# BananaDS settings

In `bananads.conf` (`key = value`, `#` for comments), found in `$BANANADS_DATA`. That is
`/storage/.config/bananads` when it exists, the current directory otherwise; `--config` names another file. Every
key can also come from the environment as `BANANADS_<KEY>` (dots become underscores, upper case:
`BANANADS_WIFI_DNS=altwfc`), which wins over the file, and from `--set key=value`, which wins over both.

| Key | Default | |
|---|---|---|
| `frontend` | `kms` without a display server (no `WAYLAND_DISPLAY` or `DISPLAY`), else `sdl` (`headless` in a build with neither) | `kms` (the handheld's panels), `sdl` (a desktop window), `headless` |
| `jit` | `on` | melonDS's JIT; `off` for the interpreter (slow, for debugging) |
| `jit.timing` | `block` | BananaJIT's timing: `block` (melonDS's JIT's level: fast memory, cycles counted per block) or `exact` (the interpreter's, cycle for cycle; slower) |
| `jit.codegen` | `new` | melonDS's JIT's code generation (patches/melonds/0007): `new` (fewer host instructions per block and per exit: cheaper exit stubs, linkable exits both ways of a block-ending branch, self loops checked inline, host flags kept in NZCV, a per-site cache for returns) or `old` (the code before 0007, byte for byte). Exact either way. Sets `MELONDS_JIT_OLDCODEGEN`; each part is also off alone with its `MELONDS_JIT_NO<name>=1` (docs/PERF.md lists them). `MELONDS_JIT_NOFASTLDM=1` keeps block loads (LDM, POP) off the fastmem path (0008). `MELONDS_JIT_LOOPREGS=1` (or `jit.loopregs=on`) turns on loops that keep their guest registers in host registers (its HeartGold hang was fixed by patch 0381; docs/PERF.md) |
| `jit.loopregs` | `on` (unless MELONDS_JIT_LOOPREGS is in the environment) | `on`: a block that loops back to its own start keeps the guest registers it uses in host registers round the loop (melonDS 0007's LOOPREGS; patches/melonds/0381 fixed its HeartGold hang, 0382 lets loops with a branch followed when taken and ARM single-register LDM/STM in, 0384 loops with block transfers of several registers, 0385 an ARM9 loop's RegionCodeCycles stored once at its entry; with J4's 0361 such a branch's R15 is stored by its exit). Exact (audio gate: tap identical). HeartGold bench FF (in-run A/B): LoopMode +2.3%, 0385 +1.3% more. Sets `MELONDS_JIT_LOOPREGS=1`; `off` unsets it; parts off alone: `MELONDS_JIT_NOLOOPFOLLOW=1`, `MELONDS_JIT_NOLOOPXFER=1` (all block transfers), `MELONDS_JIT_NOLOOPMULTI=1` (several registers), `MELONDS_JIT_NOLOOPCODE=1` (0385); `MELONDS_JIT_LOOPLOG=1` logs every compiled self loop and whether it qualifies (`why=`: 1 yes, 1x instruction x not compiled/followed, 4x an R15 operand, 7x a block transfer/MSR/MRS/BL pair); `MELONDS_JIT_LOOPRELINKOLD=1` brings the hang back (for tests) |
| `jit.slice_chain` | `on` | when the ARM9's slice ends inside a chain of JIT blocks and the slice loop would only keep time (no event or timer due, the geometry engine idle, the ARM7 halted or ahead, no DMA), the exit stub does that bookkeeping and goes on into the next block instead of returning to the loop (patches/melonds/0030). Exact: the slice ends stay where they were. Sets `MELONDS_JIT_SLICECHAIN`; off with `jit.codegen=old` |
| `jit.region_pair` | `on` | with `core.fast_loop`, when a CPU's PC leaves its code region (the ARM9 calls between ITCM and main RAM, the ARM7 goes through its BIOS for IRQs and SWIs: ~1500 and ~370 times a frame in Mario Kart DS's race start), the slice loop checks the region it last left (ARM9: ITCM or main RAM; ARM7 on a DS: BIOS, main RAM or WRAM) before setting one up again with `ClassifyAddress` and `GetMirrorLocation` (patches/melonds/0071). Exact: the same lookup, start and size as melonDS would set up |
| `jit.region_trio` | `on` | with `jit.region_pair`: two code regions a CPU left are kept for the swap back, not one, and the ARM9's BIOS and the ARM7's shared WRAM can be kept too (an IRQ takes the ARM9 main RAM -> BIOS -> ITCM handler -> BIOS -> main RAM; the ARM7's sound driver runs in shared WRAM and goes through its BIOS); the slice after a CPU wakes up swaps too (patches/melonds/0087). Mario Kart DS's race start: region setups ~640 -> ~20 a frame. Exact. `off`: `jit.region_pair`'s own way |
| `jit.lookup_prefetch` | `on` | when a CPU's slice ends in the slice loop, the block-lookup table slot of its next PC is prefetched, so the lookup at its next turn (after the other CPU's turn) doesn't stall on a cache/TLB miss in the sparse table (HeartGold: the two lookup loads were 2.3% of the emulator's thread) (patches/melonds/0120). A cache hint: exact. `off`: no prefetch |
| `jit.ldm_mainram` | `on` | the ARM9's LDM/STM sites that take the slow path (a site that once faulted stays a call) do a block whose words are all in main RAM in one loop: the same loads, and the same code check before each store, in the same order, instead of an out-of-line call per word (HeartGold: ~17k such words a frame) (patches/melonds/0121). Exact (the JIT charges the cycles in the compiled code). `off`: word by word as before |
| `jit.divblock` | `on` | an STM whose words all fall on the divider's parameters (0x04000290-29F) or the square root's (0x040002B8-2BF) writes them in order and starts the unit once, instead of a cancel + schedule of its event per word (HeartGold: ~243 of each a frame) (patches/melonds/0122). Exact: the same registers and the same event at the same time. `off`: word by word |
| `jit.entry_x26` | `on` | ARM_Dispatch sets the JIT's fast memory base (x26) itself, so the AArch64 JIT's blocks have no 12-byte entry prologue (patches/melonds/0040, the first session's 0024; docs/PERF.md "The JIT's code footprint"). Exact. `off` sets `MELONDS_JIT_NOENTRYX26=1` (the prologue back); `jit.codegen=old` implies off |
| `jit.pinregs` | `300f` | AArch64 JIT: a hex mask of guest registers r0-r14 (at most 7; `300f` = r0-r3, r12, r13) that keep a fixed callee-saved host register across linked blocks instead of being loaded at every block's entry and stored at its exit (patches/melonds/0300, `MELONDS_JIT_PINREGS`; docs/PERF.md "PINREGS"). Exact (the on-panel audio test's emulated sound is bit-identical). HeartGold's grass at FF: +3% emulated/s. `off` unsets it; `jit.codegen=old` implies off |
| `jit.dyncold` | `on` | a return through a register (bx lr, pop {pc}) keeps the miss way of its per-site cached exit in the JIT's far region: 16 bytes less in the block (patches/melonds/0041). Exact. `off` sets `MELONDS_JIT_NODYNCOLD=1` (the old code, byte for byte) |
| `jit.flagstub` | `off` | an exit through ExitCheck/ExitCheckPC with the guest's flags still in the host's NZCV has its stub put them in the CPSR, instead of three instructions in every such block (patches/melonds/0042). Exact on every check, but off by default: no check catches a mistake in ExitCheckPCF's flags (docs/PERF.md, "Mario Kart DS's race start"). `off` sets `MELONDS_JIT_NOFLAGSTUB=1` (the old code, byte for byte); `on` unsets it |
| `jit.exits` | `on` | J3 exit/dispatch work (patches/melonds/0341-0344, docs/PERF.md "JIT exits and dispatch"): exit stubs go on past an IRQ the CPU has masked (0341), a dynamic exit to another code region swaps the region itself (0342), a cached indirect exit learns a second target (0343) and keeps its key in instructions (0344), a conditional indirect jump ending a block is a cached exit both ways (0345), the ARM9's IRQ entry and restoreCPSR jumps run through one inlined function each (0346). Exact (same checks, same blocks, same cycles). `off` sets `MELONDS_JIT_NOSTOPMASK`, `NOREGIONSTUB`, `NODYN2`, `NODYNIMM`, `NOCONDDYN`, `NOFASTIRQ` (each also alone) |
| `jit.hugepages` | `on` | the JIT's 32 MB code memory aligned to 2 MB and `madvise(MADV_HUGEPAGE)`'d before its first touch, so a kernel with transparent huge pages in `madvise` mode (BananaLinux's) maps the stubs, blocks and far region with 2 MB pages: a few TLB entries instead of ~1,100 for Mario Kart DS's 4.4 MB of blocks (patches/melonds/0085). The JIT's first reset logs `[jit] code memory at <addr>, 32768 kB, N kB on huge pages`. Emulation doesn't change. `off` sets `MELONDS_JIT_HUGEPAGE=0` (the old 16 KB alignment) |
| `jit.cp15nop` | `on` | an ARM9 `MCR p15` to a cache or write buffer operation (c7: clean/invalidate a data cache line, drain the write buffer...), which melonDS's CP15 ignores, compiled to its cycles instead of the interpreter's call; user mode (the undefined instruction exception) keeps the call (patches/melonds/0086). Mario Kart DS's race start issues ~1,000 a frame (NitroSDK's `DC_*Range` loops). Exact. `off` sets `MELONDS_JIT_NOCP15NOP=1` (the old code) |
| `jit.fastclz` | `on` | the AArch64 emitter's `CountLeadingZeros` (inside `IsImmLogical`, the check for an AND/ORR/EOR immediate) by CLZ instead of a bit-by-bit loop of up to 64 rounds: the JIT compiles faster, the code it emits is byte for byte the same (patches/melonds/0088). `off` sets `MELONDS_JIT_SOFTCLZ=1` (the loop) |
| `jit.stats` | `0` | a debug readout of the JIT (patches/melonds/0400): `N` > 0 logs a `[jit] stats` line every N frames, per frame: blocks compiled (ARM9/ARM7, Thumb share, instructions per block), restored, removed (invalidated), `InvalidateByAddr` calls, JIT resets, the slice loop's block dispatches per CPU, exits through ExitCheck/ExitCheckPC and DynExit/DynExitA (entries, and how many went back to the loop; the rest went on into a block: linked), self-loop round trips (not LoopMode), SliceChain9 calls and how many chained, link requests and links made. Sets `MELONDS_JIT_STATS`. With it on the exit stubs count (a few host instructions each: a little slower, emulation identical: audio tap identical on the panels); `0`: nothing counted, the stubs as without it |
| `jit.iofast` | `on` | direct routes for the JIT's slow memory paths: main RAM block transfers, VRAM, the GX FIFO and command ports, IE/IF/IME/DISPSTAT/VCOUNT/KEYINPUT reads (patches/melonds/0005). Exact. Sets `MELONDS_IOFAST`; `MELONDS_IOFAST_ROUTES` picks single routes, `MELONDS_IOSTATS=n` prints the slow accesses by address from frame n |
| `jit.vramfast` | `on` | VRAM with one bank at a 16 KB page written and read straight to the bank (with the dirty bit and the capture check), OAM and palette straight to the GPU (patches/melonds/0010). Exact. Bit 1 of `MELONDS_MEMFAST` |
| `jit.iodirect` | `on` | the divider, square root, IPCSYNC/IPCFIFOCNT, the IPC FIFOs and IME/IE/IF read and written straight to their state, other IO registers without the ARM9Read*/ARM7Read* dispatch, one function per hot register for the JIT's static-address calls (patches/melonds/0010). Exact. Bit 2 of `MELONDS_MEMFAST` |
| `jit.wram7fast` | `on` | the ARM7's slow loads and stores (and LDM/STM) to its own WRAM at 0x03800000 straight to it on the DS: the JIT's code check, then the store, without the `ARM7Read*`/`ARM7Write*` dispatch, a block's region checked once (patches/melonds/0072). In Mario Kart DS's race start ~3,700 words a frame, the sound driver's state in pages that hold its code. Exact. Bit 8 of `MELONDS_MEMFAST` |
| `core.slice` | `64` (`auto` at `render.scale=2`) | the scheduler slice: the most system cycles (33.5 MHz) the ARM9 and then the ARM7 run before they are interleaved again (melonDS's `kMaxIterationCycles`, patches/melonds/0003). `64` is melonDS's. Longer is faster (on the RG DS, 256 gave +8.5% and 512 +10% in HeartGold) and an accuracy trade: coarser ARM9/ARM7 interleaving, each CPU seeing the other's writes up to a slice late, which matters for IPC handshakes and anything timing-sensitive between the CPUs; scheduled events (timers, DMA, video, IRQs from them) stay on time, except ones the ARM7 starts inside a slice, which run at its end. `auto`: adaptive, `64` near IPC and `core.slice_idle` away from it. Test many games before changing the default. An event due within 8 cycles of a slice's end (`kIterationCycleMargin`) ends it instead |
| `core.slice_idle` | `512` with `auto`, `core.slice` otherwise | the slice while neither CPU has touched the IPC registers (IPCSYNC, IPCFIFOCNT, IPCFIFOSEND, IPCFIFORECV) or WRAMCNT for `core.slice_hold` cycles; any value other than `core.slice` makes the slice adaptive. Handshakes through main RAM alone aren't seen (fast memory), and the first IPC access after a quiet spell still lands in a long slice |
| `core.slice_hold` | `4096` | how many system cycles (4096: about two scanlines) after an IPC access the short slice stays |
| `core.slice_stats` | `0` | every this many frames, log the IPC accesses per frame and the share of time near one (the short slice's share), for tuning `auto` per game |
| `core.fast_gxdma` | `off` | DMA words from main RAM to the geometry FIFO go straight to the 3D engine instead of through melonDS's bus and IO dispatch (patches/melonds/0004). Exact: the same results and timing; off until measured on the handheld |
| `core.fast_spu` | `off` | the mixer skips sound channels that are off (patches/melonds/0004). Exact; off until measured |
| `core.fast_mix` | `on` | the SPU runs only the sound channels due to take a sample (all of them after a sound register write) and keeps the others' output, sums the mixers with NEON, and sound DMA and capture read and write main RAM without the bus dispatch (patches/melonds/0013). Exact: the same audio byte for byte (`headless.audio_dump`) and the same RAM |
| `core.fast_samples` | `on` | with `core.fast_mix`, a sound channel due to take PCM16 or ADPCM samples takes them with its state in registers and ADPCM's step from tables; its start, loop, end and FIFO refills go through melonDS's code (patches/melonds/0070). | `headless.input` | none | scripted presses: `<frame>:<keys>[:<frames held>]`, comma-separated, keys joined by `+` (`a b select start right left up down r l x y`), held 6 frames by default: `600:start,900:a:10` |
| `log.file` | none | a copy of the log (stderr always gets it) |
| `log.level` | `1` | 0 debug, 1 info, 2 warnings, 3 errors |
| `log.time` | `off` | `on`: each log line starts with the seconds since boot (`CLOCK_BOOTTIME`, as `/proc/uptime`), to time a start against the launcher and the panels |
| `prof.hz` | `0` | a sampling profiler of the emulator's thread (`src/prof.cpp`), for a handheld without `perf`: `N` samples a second of that thread's CPU time (a `CLOCK_THREAD_CPUTIME_ID` timer signalling that thread alone; the kernel checks it at its tick, so it gets at most `CONFIG_HZ`, and the report says what it got). At the end a report: the share in JIT-generated code, by module, the top functions, the same by C++ class, and with `MELONDS_JIT_PERFMAP=1` the hottest JIT blocks (`mj9_`/`mj7_<guest address>`) and stubs. The emulation doesn't see it: the same frames, RAM and sound. `0`: off |
| `prof.source` | `auto` | what makes `prof.hz`'s samples: `task-clock` (a perf event on the thread's CPU time: a high-resolution timer, any rate), `cycles` (the core's cycle counter, `prof.hz` samples per 10^9 cycles), `timer` (a POSIX CPU-time timer, which the kernel checks only at its tick: at most `CONFIG_HZ`, 250 on the RG DS). `auto`: `task-clock`, else `timer` (the report says which it used, and why) |
| `prof.pmu` | `on` | with `prof.hz`: the core's own counters on the same thread and frames (`perf_event_open`, as `perf stat`): cycles, instructions, branch misses, L1I and L1D misses, iTLB misses, per frame and per 1000 instructions, the IPC and the clock while running; a line in the report. Needs the kernel's `CONFIG_HW_PERF_EVENTS` and the A55's PMU (BananaOS's kernel has them) |
| `prof.from`, `prof.frames` | `0`, `0` | the first frame sampled (e.g. `headless.measure_from`'s), and how many (`0`: up to the quit; the report is made then) |
| `prof.out` | the log | the report's file |
| `prof.syms` | the binary itself | the file to take function names from: the unstripped build of this same binary (Buildroot strips the one on the device; the report warns when the file is another build's). Without names the report gives `bananads+0x<offset>` |
| `prof.raw` | none | also every sampled address with its count and the modules' ranges, to resolve offline (`addr2line -f -C -e <unstripped binary> <address>`) |
| `prof.top`, `prof.samples` | `40`, `262144` | the functions listed; the samples kept (8 bytes each, allocated when sampling starts; later ones are counted as dropped) |
| `prof.thread` | `emu` | `present`: `prof.hz` samples the KMS presenter (the main thread: commits, the shader pass, input) instead of the emulator's thread; the report's CPU-time figures stay the emulator's thread's, the shares are the presenter's |

## The handheld's buttons (`frontend=kms`)

The pad as the DS's (A east, B south, X north, Y west, L, R, Start, Select, the d-pad), read and never grabbed: the
volume keys and the lid stay the system's. F (`BTN_MODE`) + Start: quit (with the resume state). F + R: save to slot
1. F + L: load slot 1. While F is held the game sees no buttons. A keyboard works too: arrows, Enter (A), Backspace
(B), X, Y, Page Up / Page Down (L / R), S (Start), Tab (Select), F1 (F); Esc quits. `SIGTERM`, `SIGINT` and `SIGHUP`
quit the same way, writing the resume state and the save.

## The window's keys (`frontend=sdl`)

Arrows: the D-pad. X / Z: A / B. S / A: X / Y. Q / W: L / R. Enter: Start. Right Shift or Backspace: Select. The
mouse on the bottom screen: the stylus. F1: blow into the mic. F5-F7: save to slot 1-3. F9-F11: load slot 1-3.
Esc: quit (with the resume state).
