# G2: GPU 3D renderer (melonDS classic GL -> GLES 3.1) for BananaDS 3x/4x

Worktree ~/mk4x/wt/G2, branch mk4x/G2 (from mk4x/integ b1c7cc9), build ~/mk4x/obj/G2/bananads.

## Design (13:35)
- `render.gpu3d=gl|compute` (default off), only at render.scale 3/4 with the Banana 2D engine; kms.shader forced none.
- Host `GpuRenderer3D` (src/gpu3d_host.*, a melonDS Renderer3D): thread `bds-gpu3d` with its own surfaceless EGL
  GLES 3.1 context (EGL dlopen()ed, GL entry points via eglGetProcAddress, src/gpu3d_gl.h: no link dependency;
  fails -> Gengis). One frame in flight: RenderFrame (emu thread, line 215) waits for the previous frame's read-back,
  calls backend Prepare (copies all DS state: texture cache incl. decode, clear bitmap, vertex/index buffers, UBO),
  kicks the GL thread. GL thread: GlRender, a pack pass (deinterleaves into Gengis's 4x row layout and converts to
  melonDS's 3D pixel format in the shader), glReadPixels in 4 chunks of 48 DS lines, each chunk released to the 2D
  thread (SetHiresRows WaitRows/RowsGen like Gengis). So 2D, display capture (1x quarter 0), presenter: unchanged.
- Backend `Gl3DBackend` (src/gl3d_backend.cpp + gl3d_shaders.h): melonDS GPU3D_OpenGL.cpp ported; texture cache's GL
  work recorded on the emu thread (virtual handles) and replayed on the GPU thread; edge/fog passes via a colour-only
  FBO (GLES feedback-loop rule); capture-texture paths and "better polygons" left out. Shaders validated with glslang.
- Exactness argument: the renderer only reads GPU3D render state + VRAM flats on the emu thread (as Gengis does);
  emulation code untouched; gate = mktap at 4x vs tapref-2x.
- Commit 2b17937.

## Runs
- g2-a1 (2b17937, 4x none, gpu3d=gl, glReadPixels direct): **12.9 fps**, picture correct (MKDS race at 4x, LOOKED:
  ~/mk4x/runs/g2-a1/shots/t026.png). bds-gpu3d 46%, emu 16%, 2d 11%. Per frame: prepare 1.0-1.4 ms (emu thread),
  GL submit 9-13 ms CPU, GPU wait 29-42 ms, read-back 28 ms (3 MB from uncached memory, ~110 MB/s).
- g2-a2 (+ sampler objects, PBO read-back, glFinish timing): GPU time of the 3D draw 47 ms/frame (glFinish), PBO
  map+memcpy 22 ms: still an uncached read. GPU 600-800 MHz. => two problems: GPU time, and the read-back.
- Next: render.gpu3d_read=heap (pack pass draws into two /dev/dma_heap/system dma-bufs = CPU-CACHED pages imported as
  EGL render targets; they ARE the 2D's 3D rows: no copy, DMA_BUF_IOCTL_SYNC once per frame) + per-phase GPU timing.
- g2-a3 (e7a9eb3 code: heap read-back + glClear first + samplers; run with render.gpu3d_finish=1 = instrumented, 25 s):
  **20.6 fps** (18 -> 25), picture correct (LOOKED: runs/g2-a3/shots/end-crtc1.png: race, translucent item boxes,
  kart shadows). Read-back 28 ms -> **0.16 ms** (the GPU draws straight into cached dma-heap buffers; the 2D reads them
  after one DMA_BUF_IOCTL_SYNC). Threads: emu 27%, gpu3d 25%, 2d 17.5%, audio 3.5%, presenter 2.4% (~76% of 400%:
  the CPU is now mostly idle). GPU at 800 MHz all run, 49-57 C. GPU phases (glFinish each): clear 2.0, **opaque 20,
  translucent 13-15 ms**, final 0.13, uploads 0.08 per frame; 880-940 polygons. => the GPU (Mali-G52, panfrost) is
  the limit: ~35 ms/frame of 3D vs 16.7 needed.
