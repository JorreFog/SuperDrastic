## Checkpoint 14:40: 4x fps vs CPU clock (race bench, 4x none, cpugov.max_khz cap, same first 31 windows = 1860 frames, cold start)
| clock | fps (windows 1-31) | vs 1992 | temp end of ~45 s |
|---|---|---|---|
| 1992 (PIN) | 47.19 / 47.26 (off), 47.67 (emu_share=1) | - | 68-69 C |
| 1608 | 46.47 | -1.5% | ~62 C (trip only at ~77 s) |
| 1416 | 41.17 | -13% | 62 C |
| 1104 | 34.55 | -27% | 57 C |
The knee is 1608: above it 4x is memory-bound (clock buys ~nothing, only heat); below it fps falls with the clock.
The kernel's thermal cap at 70 C swings between 1800/1608/1416 -> the 1416 phases are the ones that cost frames.
Suggestion for the 60 fps target: cpugov at 4x should never pick 1992/1800 just for "late" frames when 1608 does as
well (cooler = later trip); not implemented (needs a fps-vs-clock probe in cpugov; data above for M1's call).
