## Checkpoint 11:45
- Baseline facts (m2-base-p1 perf-instrumented, m2-base-s1 plain): the demo race at 4x runs 31-47 fps (title 60).
  render.gengis_stats: Gengis bins **45-81 ms CPU per rendered 3D frame** (every frame renders), 1.3-2.9 M opaque +
  0.03-1.2 M translucent span pixels a frame (786K screen pixels: overdraw ~2.8x), 180-1200 opaque polygons,
  d3 0x1d (textures, alpha test, blending; no fog, no edge marking). The emulator's thread drew 16.5% of the bins
  (3361 of 20340). Max bin 6-13 ms.
- Where the Gengis threads' time goes (perf, 12.3K samples): asm kernels ~58% (rast_kern_h11010 31% = w-buffer,
  direct texels, opaque, flat; h12010 11%; h14110 5.7% translucent paletted), **line_px 14.3%** (the scalar per-pixel
  reference: decal/toon/highlight polygons have no NEON or asm path at hi-res), gx4_render_bin 8.5% (clear + output),
  gx_polygon 4.1%, Convert 3.9% (serial at the frame's start), libc 2.3%, kernel 4%.
  perf stat: Gengis IPC ~0.57.
- Work 1 (code done, measuring): gengis/hrneon.c = NEON batches for decal/toon/highlight on the hi-res layouts,
  line_px lane for lane (render.gengis_hrneon, default on at 3x/4x, off at 2x: 2x unchanged).
- Exactness tool: `render.gengis_verify=1` renders every bin a second time on the reference paths (thread-local
  gx_ref: line_px, no defer, ...) into a scratch buffer and memcmps it with what was written; logs mismatches and an
  exit summary "[gengis] verify: N bins ... M differ". In-run A/B aid: `render.gengis_optab=0,1,3` cycles option masks
  (1 hrneon, 2 defer) every render.gengis_ab_secs, with a stats line at each switch.

## Checkpoint 12:30
- **hrneon (commit b84bc86), READY on BOARD**: the 14% "line_px" was mostly SHADOW polygons (MKDS kart shadows are
  shadow volumes: mask + shadow, mode 3), which the hi-res pipeline always ran on the scalar line_px; decal/toon/
  highlight too. hrneon.c now does all four in NEON, lane for lane with line_px (shadow: line mask, stencil set by the
  mask's failing depth test, the shadow's stencil/id test). Default on at 3x/4x, off at 2x (2x paths unchanged).
  - m2-ver1 (verify=1, hrneon v1 + defer cycled): 10692 bins, 0 differ. m2-ver2 (decal/toon/highlight only):
    4.695 vs 4.779 ms CPU a bin (-1.8%). m2-ver3 (+ shadows): **3.584 vs 4.673 ms a bin (-23%), 13716 bins, 0 differ.**
  - render.gengis_defer (existing deferred shading) at 4x MKDS: m2-ab1 in-run A/B 37.7 vs 33.0 ns per span pixel:
    worse, dropped (as in HG).
- New profile (m2-p2, hrneon build, race segment): h11010 29.6%, **h13110 24.2%** (translucent paletted textures),
  gx4_render_bin 9.1%, hb_10114 (NEON shadow) 8.9%, h11000 4.6%, gx_polygon 4.3%, Convert 3.2%.
  perf stat on the Gengis threads: IPC 0.41; L3 (the A55s' "L2D" events = the DSU's 512 KB L3) 371M accesses,
  **66M misses (to DRAM) in 8 s** ~ 13 MB a frame. The eager clear of each 4x sub-bin context (278 KB of colour +
  attributes, three threads = more than the L3) sends the cleared lines to DRAM before polygons reach them.
- Work 2 (measuring): render.gengis_lazy: the context cleared 64 px at a time just before a polygon's span reaches
  it (margin for the kernels' reads around a span), the rest before the resolve; same values wherever anything reads.
