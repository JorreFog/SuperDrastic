- Item 3, new approach (kms.grid_cpu, default on): at 4x ds-grid-2x is 1:1, i.e. a per-byte function of the input byte
  and the place in the DS pixel's 4x4 cell. shader_grid4_lut draws a test picture through the FILE's shader on the
  GPU, reads it back, and builds two 256-byte tables (cell / grid line), accepted only if every pixel of the picture
  agrees (all bytes x all 16 places). The Banana 2D engine then writes the 4x frame with the grid in (NEON: the 6-bit
  channel looked up with one vqtbl4q instead of Expand6, so no extra memory traffic; scalar paths + Fill via the 8-bit
  tables), and the presenter skips the GPU pass for those frames (no Mesa, no GPU, GPU floor released). The NEON grid
  writers are self-checked at turn-on against "ungridded writer + tables per byte" for all 64 levels x lanes x
  brightness modes; any failure -> grid stays on the GPU. Testing on the panels now (m4-mk-gcpu).
- Known difference: F + L2 screenshots of a CPU-gridded frame contain the grid (before: taken before the shader).
