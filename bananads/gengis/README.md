# gengis/: Gengis Engine in BananaDS

SuperDrastic's 3D rasterizer (Gengis Engine), as melonDS's 3D renderer at 1x or 2x (`render.renderer=gengis`, `render.scale`, the default
on aarch64). See `docs/GENGIS.md` for what it does and how it differs from melonDS's renderer.

## Where the files come from

Copied unchanged from SuperDrastic `src/rast/` at a63fe5b (PR #8, branch `claude/gengis-a55-scheduling`):
`fused.c`, `fused.h`, `fused_neon.c`, `fused_asm.c`, `defer.c`, `rast_kern.S` (generated by `kerngen.py`, with
`kernsched.py`), `walk_impl.h`, `fogzero.h`, `ds3d.h`, `rast.h`, `spec/edges.h`.

Written for BananaDS:
- `gx.c`, `gx.h`: the 1x pipeline (bins, contexts, the walk, the clear, the resolve, the output); `gx2.c` compiles
  it again at 2x (`render.scale=2`), 32-line bins of 512 pixels, each row stored as its even then its odd pixels.
- `gx_resolve.h`: hr.c's fog and edge-marking passes, re-parameterised for 256-pixel lines.
- `../src/gengis_renderer.cpp`: the melonDS side (polygons, textures, the render threads).

To take a newer rasterizer, copy the same files again and rebuild. `gx.c` depends on f_run's interface, the
kernels' layout (the hi-res set, `rast_kern_h*`) and walk_impl.h's macros.

## Provenance

The pixel pipeline reproduces DraStic r2.5.2.2's 3D routines bit for bit. It was written against SuperDrastic's
`src/rast/spec/`, C ports of those routines made from the reverse engineering. That conflicts with the rule in
`docs/JIT.md` ("ideas yes, DraStic's code no"). The owner decided on 2026-10-11 to use it in BananaDS anyway, as a
recorded exception to that rule.
